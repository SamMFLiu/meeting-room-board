# 會議室預約看板

單機、純前端的會議室預約看板。打開頁面就能看到某一天 3 間會議室的預約狀況，並且可以新增、修改、取消預約，系統會自動擋下重複預約。

這是課堂 Lab 作業：不需要後端、不需要登入、不需要建置工具，只用原生 HTML / CSS / JavaScript，資料存在瀏覽器的 `localStorage`。完整需求與驗收標準見 [spec.md](spec.md)。

## 功能

- **單日時段表**：橫軸是 3 間會議室，縱軸是 08:00–18:00，每 30 分鐘一格；已預約的時段以色塊顯示主題、預約人與起訖時間。
- **日期切換**：前一天／今天／後一天按鈕，也可以用日期選擇器直接跳到某一天。
- **新增預約**：點一格就是預約那 30 分鐘；也可以按「新增預約」，預設會帶入下一個還能預約的 30 分鐘。不需要登入，填預約人姓名即可。
- **拖曳多選**：在同一間會議室的欄位按住拖曳，可以一次選取連續多格；手機上要先長按約 0.35 秒再拖曳（直接滑動是捲動畫面）。拖到已預約或已過去的時段會停住。
- **修改預約**：點色塊開啟詳細視窗，可以修改所有欄位。已經開始的預約只能檢視和取消。
- **取消預約**：色塊右上角的「取消」按鈕或詳細視窗裡的「取消預約」，都會先跳出確認。
- **衝突檢查**：同一間會議室的時段不能重疊，緊鄰的時段（例如 10:00–12:00 與 12:00–14:00）可以預約。新增和修改都會檢查。
- **輸入驗證**：必填欄位、結束時間要晚於開始時間、時間要對齊 :00 或 :30、要落在 08:00–18:00、不能預約已經過去的時段。
- **匯出 CSV**：下載目前日期的預約清單（會議室、時段、預約人），檔案含 BOM，Excel 可以直接開啟。
- **資料保存**：重新整理或關掉瀏覽器再打開，資料都還在。

固定的 3 間會議室：大會議室（12 人）、小會議室 A（6 人）、小會議室 B（4 人）。

## 開啟與使用

直接用瀏覽器打開 `index.html`（在檔案總管雙擊即可），不需要安裝任何東西，也不需要啟動伺服器。支援新版 Chrome／Edge，手機寬度（375px）也能使用。

1. 頁面預設顯示今天的時段表。
2. 點空白的格子，或按右上角「＋ 新增預約」，填好主題與預約人後按「儲存」。
3. 點已預約的色塊可以修改；按色塊上的「取消」可以取消預約。

### 資料存在哪裡

預約資料存在瀏覽器的 `localStorage`，key 是 `mrb:bookings`。要注意：

- 資料只存在這台電腦的這個瀏覽器裡，換瀏覽器、換電腦或清除網站資料後就會不見。
- 用 `file://` 開啟和用 `http://localhost` 開啟，是兩份不同的資料。
- 要清空所有預約，可以在瀏覽器的開發者工具 Console 執行：

  ```js
  localStorage.removeItem('mrb:bookings')
  ```

## 執行測試

衝突檢查的單元測試寫在 `test.html`，直接用瀏覽器打開即可執行，不需要任何測試框架。

- 頁面頂部會顯示總結，例如「通過 9 項／共 9 項」。全部通過時是綠色，有失敗時是紅色。
- 下方表格列出每一項測試的名稱、預期值、實際值，以及 ✅ 或 ❌。

目前的測試涵蓋 `findConflict` 的這些情況：

| 類型 | 情況 | 預期 |
|------|------|------|
| 一般 | 完全相同的時段 | 衝突 |
| 一般 | 完全錯開的時段 | 無衝突 |
| 邊界 | 部分重疊（前段、後段） | 衝突 |
| 邊界 | 完全包含（新預約在既有預約內、新預約包住既有預約） | 衝突 |
| 邊界 | 緊鄰時段（接在前面、接在後面） | 無衝突 |
| 邊界 | 不同會議室的同一時段 | 無衝突 |

其他功能（拖曳、取消、匯出等）沒有自動化測試，是依 [spec.md](spec.md) 第 6 節的驗收標準手動測試，結果記錄在 [bugs.md](bugs.md)。

### index.html 與 app.js 的分工

- `app.js` 只放衝突檢查，沒有用到 DOM，所以 `index.html` 和 `test.html` 都能共用。
  - `toMin(hhmm)`：把 `"HH:MM"` 轉成當天的分鐘數。
  - `overlaps(a, b)`：判斷兩段時間是否重疊（首尾相接不算重疊）。
  - `findConflict(bookingList, data, ignoreId)`：找出與 `data` 同會議室、同日期且時段重疊的第一筆預約，沒有就回傳 `undefined`；修改預約時用 `ignoreId` 排除自己那一筆。
- `index.html` 裡的 `validate()` 負責所有輸入驗證，衝突的部分呼叫 `findConflict`。
- `app.js` 用一般的 `<script src="app.js"></script>` 載入，而且必須排在 `index.html` 主程式的 `<script>` 之前。**不要改成 ES module**：雙擊開啟時網址是 `file://`，瀏覽器會擋下 module 的載入。

## 開發規範

詳見 [CLAUDE.md](CLAUDE.md)，重點如下：

- 程式碼固定為 `index.html` + `app.js` + `test.html` 三個檔案，不要再拆分其他檔案，也不要引入外部框架或函式庫。
- 雙擊 `index.html` 就要能使用，不使用建置工具或伺服器。
- 介面文字與程式註解都使用繁體中文。
- 修改後依 [spec.md](spec.md) 第 6 節的驗收標準手動測試（包含 375px 手機寬度），並確認 `test.html` 全部通過。
